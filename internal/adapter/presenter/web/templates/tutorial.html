How to use this

Four things, in order. Everything else is discoverable by clicking around — this is for the first five minutes.

  1. Pick what to review

    Top left of the cockpit, under reviewing. Type a tag, a commit, a branch — it searches as you type. Or leave it on live, which is your working tree against HEAD and where msr opens.

    Anything in git is reviewable: one commit, a tag (everything since the previous one), a pull request, a recorded agent session, or any two points compared against each other. A signed-off review is ticked in the list, so what is left to look at is readable without opening it.

  2. Ask the assistant to read it

    The card across the top says whether it has. Press ask it to read this and it groups the files by folder, writes one sentence about what each group is for, and tells the whole change as two to five chapters. About seven seconds on a local model.

    Optional, always. Without a model you still get the grouping, the flags, the diffs and the review log — just no prose. The review never waits on the model, and the model can never assert a reason nobody gave: a rationale in the agent's own words is labelled stated, one the model guessed is labelled inferred.

  3. Ask it something more specific

    Beside the story sit two more cards: a security pass and a breaking-change check. Each runs only when you press it, and each is a separate reading of the same diff — no card is ever shown what another found.

    They are short on purpose: at most five findings, each a file and one sentence. A card that finds nothing says so plainly, and one that could not run says that instead — those two never look alike. What they report is labelled inferred: worth a look, not a verdict.

  4. Read, then annotate

    Click a filename for its diff. Under each one the assistant calls out the one to three lines actually worth reading, and flags like no-test, new-dep or swallowed-err mark what deserves a second look — those are computed offline, with no model involved at all.

    Every change takes a note and one of ok · question · objection · debt · note. That log is the thing you are producing. The prose and the assistant exist only to help you produce it.

  5. Mark it reviewed

    When you are done, mark this reviewed on the card, with a closing comment on the change as a whole if you have one. Reopening it tomorrow says so.

    And if the code moved after you signed off, it says that instead of reading as current — a verdict about a version that no longer exists is worse than no verdict.

while the agent keeps working

The page you are reading holds still. Work the agent does after you opened a review does not appear underneath you — it queues in a banner above the card, naming the files and flagging any you have already annotated. Then you choose: keep reading, include them, or review just these, which opens the new work on its own.

Separately, a small toast in the corner says when the repository moves — a commit, a tag, files changing. Clicking it opens what it names.

where you are, and what the team is doing

The history card in the panel lists recent commits and marks three things: the one you are reviewing, the ones you have already signed off, and the ones that have not left your machine. Click any row to review that commit.

If the branch tracks a remote it also shows how far ahead or behind you are, and a colleague's commit appears at the top marked incoming. msr only fetches if you start it with --fetch — otherwise it reads whatever your own last fetch brought in, because fetching talks to the network and writes refs, and msr does neither without being asked.

keys

Reading is the common case, so it has the short keys. All of them are ignored while you are typing. Press ? anywhere for this list.

  • jnext file
  • kprevious file
  • oopen or close the file
  • g / Gfirst / last file
  • [ / ]previous / next review
  • { / }previous / next repository
  • /jump to the picker
  • aask about these changes
  • rmark this review done
  • ⌘Kgo to anything
  • ⌘Zzen mode
  • ⌘Jdark, light, or follow the system

two things worth knowing

It never writes to your repository. No commits, no branches, no changes to HEAD, the index or your working tree. Snapshots go to refs of their own.

Everything is local. The only network call msr makes is to the model endpoint you started yourself. No account, no telemetry. The status page shows which model is answering and what it has cost.
