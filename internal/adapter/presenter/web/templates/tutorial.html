how to use this

Four steps, in order. Everything else is a click away — this is the first five minutes.

  1. pick what to review

    The history card lists every commit, tag and recorded run, newest first. Click a row, or walk it with [ and ]. msr opens on live — your working tree against HEAD.

    cockpit · branches for what everyone else is pushing

  2. have it read

    start review groups the files, says what each group is for, and tells the change as a few chapters. The two cards beside it — a security pass and a breaking-change check — run one at a time, only when you press them.

    All of it optional. Without a model you still get the grouping, the flags, the diffs and the log. A reason the agent gave is marked stated; one a model guessed is marked inferred; what an analyser found is reported, and names its tool and rule.

  3. read, then annotate

    Click a filename for its diff; j and k walk them. Any line takes a note, filed as ok, question, objection, debt or note.

    That log is the thing you are producing. The prose and the readings exist to help you produce it.

  4. mark it reviewed, and hand it back

    mark this reviewed closes it, with a comment on the change as a whole if you have one. If the code moves afterwards, the review says so rather than reading as current.

    Point your agent's MCP client at msr mcp and it reads the review itself, when it asks. msr never speaks first, and what you wrote arrives through a different call from what a model guessed.

worth knowing

  • It never writes to your repository. No commits, no branches, nothing touched in HEAD, the index or your working tree.
  • Everything is local. The only network call is to the model endpoint you started yourself — settings says which one is answering and what it has cost.
  • The page holds still. Work the agent does while you are reading queues in a banner instead of moving what you are looking at.
  • ? lists every key, ⌘K goes to anything, and search finds anything anybody wrote.
